# Linked order lines

`POST /ekom/order/add` and `Order.AddLinkedOrderLinesAsync` can atomically add a new parent line with multiple independently quantified child products. Typical uses are engraving, printing, gift wrapping, warranties, or product-specific services.

Each child is a normal order line. Its `OrderLineSettings.Link` contains the generated parent line key.

## HTTP request

```http
POST /ekom/order/add
Content-Type: application/json

{
  "productId": "11111111-1111-1111-1111-111111111111",
  "variantId": "22222222-2222-2222-2222-222222222222",
  "storeAlias": "Store",
  "quantity": 1,
  "linkedProducts": [
    {
      "productId": "33333333-3333-3333-3333-333333333333",
      "quantity": 1,
      "customData": {
        "orderlineName": "Anna",
        "orderlineText": "Team 2026"
      }
    },
    {
      "productId": "44444444-4444-4444-4444-444444444444",
      "variantId": "55555555-5555-5555-5555-555555555555",
      "quantity": 2
    }
  ]
}
```

The response is the updated `IOrderInfo`. When `linkedProducts` is non-empty, Ekom forces `OrderAction.New`; the root `action` value is ignored so every group has unambiguous line keys.

Each child accepts:

| Field | Required | Behavior |
| --- | --- | --- |
| `productId` | Yes | Catalog product key. |
| `variantId` | When required | Variant key belonging to that product. |
| `quantity` | No | Positive independent quantity, default `1`. |
| `customData` | No | Child-specific string values. Only `orderline*` keys become line properties. |

Root-level custom fields follow the ordinary add endpoint. `linkedProducts` itself is removed from root custom data. `ekomUpdateInformation` is rejected for linked requests; update customer information separately.

## C# API

```csharp
IOrderInfo order = await orderApi.AddLinkedOrderLinesAsync(
    parentProductKey,
    quantity: 1,
    storeAlias: "Store",
    linkedProducts:
    [
        new LinkedOrderLineRequest
        {
            ProductId = engravingProductKey,
            Quantity = 1,
            CustomData = new Dictionary<string, string>
            {
                ["orderlineText"] = "Team 2026",
            },
        },
    ],
    settings: new AddOrderSettings
    {
        OrderAction = OrderAction.New,
        VariantKey = parentVariantKey,
    },
    ct);
```

The collection must contain at least one non-null child. Ekom resolves and validates the parent and every child before it changes the persisted basket.

## Atomic staging

Ekom stages the complete group against a cloned order, then persists once. Product/variant resolution, quantities, stock checks, pre-add events, discounts, and line construction occur before the save. If any of those operations or persistence fails, none of the proposed lines are added.

Added/updated notifications run after persistence. Notification failures are logged and do not roll back a successful basket update.

Product and variant prices, availability, stock validation, discounts, consent/tracking, and Algolia query tracking use the same logic as ordinary additions. Parent and child custom data are kept separate.

## Basket behavior

- Parent and child quantities are independent.
- A child can be updated or removed independently.
- Removing a parent also removes lines whose `Settings.Link` directly targets that parent.
- Removing a child does not remove its parent or siblings.
- Children contribute to quantity, tax, discounts, stock and monetary totals as ordinary lines.
- This endpoint creates one direct parent-to-child level; it does not accept nested child groups.
- Adding the same product again creates another parent group rather than merging into an existing parent.

## Razor form

Browser code can convert flat child controls into `linkedProducts` before posting JSON to the add endpoint:

```html
<script>
document.querySelector('#personalized-product').addEventListener('submit', async event => {
  event.preventDefault();

  const form = event.currentTarget;
  const payload = Object.fromEntries(new FormData(form).entries());
  payload.quantity = Number(payload.quantity);
  payload.linkedProducts = [{
    productId: payload.linkedProductId,
    variantId: payload.linkedVariantId || null,
    quantity: Number(payload.linkedQuantity),
    customData: { orderlineText: payload.linkedOrderlineText }
  }];

  delete payload.linkedProductId;
  delete payload.linkedVariantId;
  delete payload.linkedQuantity;
  delete payload.linkedOrderlineText;

  const response = await fetch(form.action, {
    method: 'POST',
    credentials: 'same-origin',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify(payload)
  });

  if (!response.ok) throw new Error(await response.text());
});
</script>
```

`/ekom/order/add` does not validate the antiforgery field generated by `Html.BeginEkomForm`. If the storefront uses this JSON pattern, add and validate host-level CSRF protection rather than assuming the helper's hidden token protects the request.

`Object.fromEntries` retains only the last control for repeated names; handle repeated values explicitly when the form has more than one linked item.
